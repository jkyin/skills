# 阶段 6：复盘与沉淀

同一问题连续纠正仍失败，或交付后考虑沉淀长期规则时读取。

## 当下修复

同一个问题连续纠正仍失败时，先判断根因：

- 规格或提示词缺少约束：更新 `SPEC.md` 或初始提示。
- 仓库事实判断错误：补充代码、日志或运行证据。
- 对话包含互相冲突的旧方案，或上下文已明显臃肿：compact、`/clear` 或开新 task，并用修正后的规格重新开始。
- 仍属于同一个连贯问题且历史有价值：保留当前 task，不要只为“干净”丢掉有用决策。

## 长期沉淀

重复错误不一定都应该写进 `AGENTS.md` / `CLAUDE.md`。先选择正确的承载面：

| 内容 | 承载位置 |
|---|---|
| 稳定的仓库约定、非显然命令、长期架构约束 | `AGENTS.md` / `CLAUDE.md` |
| 能机械判定的要求 | 测试、lint、类型检查或 hook |
| 跨任务重复出现的操作流程 | skill |
| 一次性需求、临时决策、当前实现范围 | `SPEC.md` / issue / task |
| 易变化的外部事实或完整 API 文档 | 官方链接或项目文档，不复制进记忆文件 |

只有观察到稳定、重复的模式后才提出长期规则。除非用户明确要求，不要自动修改持久化指令文件；先给出一条具体、可执行的候选规则和证据。

候选规则提示词：

```text
这个问题已重复出现。做一次复盘：
1. 根因是规格、仓库事实、缺少机械门禁，还是缺少持久规则？
2. 最小且正确的承载面是什么？
3. 如果应写入 AGENTS.md / CLAUDE.md，只给出一条具体、可执行的候选规则及证据，不直接写文件。
```

**持久化指令的纪律：**

- 保持简短。删掉不会导致重复犯错的内容。
- 只写 agent 无法从代码直接推导、且长期稳定的项目事实。
- 不写标准语言约定、一次性实现细节、经常变化的信息或「写整洁代码」等空话。
- 外部平台、API、政策和安全规则必须保留可追溯来源，并在可能变化时重新核对。

**文件位置：**

| Agent | 持久化指令 | Skill 目录 |
|---|---|---|
| Claude Code | `CLAUDE.md`（项目根、用户级或子目录） | `.claude/skills/` |
| Codex | `AGENTS.md`（仓库根、`~/.codex/` 或子目录，就近规则生效） | `.agents/skills/`（团队）、`$HOME/.agents/skills`（个人） |

跨 agent 共用规则时，使用一个明确的规范源和可验证的同步方式。不要假设不同 agent 都支持相同的 import 语法；只有在目标工具和环境确认支持时才使用软链接或 import。
