# 审查清单

从上往下查，越靠前影响越大。每条命中时，按「问题 → 原则 → 具体改法（带刻度值）」输出。原则细节见 [principles.md](principles.md)，数值见 [tokens.md](tokens.md)。

## 1. 层次（最先查）

- [ ] 一眼能说出这屏最重要的内容和唯一的主操作吗？
- [ ] 是否所有东西都在抢注意力？次要信息有没有被弱化？
- [ ] 层次是否只靠字号？主要内容是否过大、次要内容是否过小到难读？
- [ ] 文字颜色是否控制在 2–3 级？字重是否控制在两种（400/500 + 600/700）？
- [ ] 小字有没有用低于 400 的字重？
- [ ] 彩色背景上有没有灰色文字或白色半透明文字？
- [ ] 想突出的元素不突出时，有没有尝试弱化竞争元素？
- [ ] 有没有能去掉或合并进值里的「标签：值」？保留的标签是否被弱化？
- [ ] 区块标题是否因为语义层级而被做得过大？
- [ ] 实心图标是否比旁边文字更抢眼？过细的浅色边框是否该加粗而非加深？
- [ ] 按钮是否分了主/次/三级？危险操作是否在非确认场景就用了大红实心？

## 2. 间距与分组

- [ ] 间距、尺寸是否都在刻度内？有没有 13px、18px、22px 之类的随意值？
- [ ] 整体是否太挤？（大多数自造界面都留白不足）
- [ ] 组外间距是否明显大于组内间距？标签与输入框、标题与上一段、列表项之间有没有含糊？
- [ ] 内容是否被无谓地拉满屏宽？表单、卡片、登录框是否有合适的 max-width？
- [ ] 侧边栏等是否该用固定宽度而不是百分比？
- [ ] 小屏上标题、按钮 padding 是否被等比缩放成不合适的尺寸？

## 3. 文字

- [ ] 字号是否在刻度内、数量是否克制？是否用了 em 导致嵌套字号跑出刻度？
- [ ] 正文字体是否 x 高度足够、不是窄体？
- [ ] 段落每行是否在 45–75 字符内（中文约 25–40 字）？与图片混排时段落是否单独限宽？
- [ ] 同一行不同字号是否按基线对齐？
- [ ] 行高是否随行长、字号调整（长行更大，大标题更小）？
- [ ] 链接密集的界面，链接是否过于抢眼？
- [ ] 超过两三行的文本是否被居中？表格数字是否右对齐？两端对齐是否开了断字？
- [ ] 全大写文字是否加了字距？用正文字体做的大标题是否该收紧字距？

## 4. 颜色与对比度

- [ ] 颜色是否来自预定义色阶？有没有 `lighten()/darken()` 或零散 hex？
- [ ] 灰阶是否够用（8–10 级）？是否用了纯黑？
- [ ] 浅色和深色色阶是否发灰（两端饱和度不足）？
- [ ] 灰色冷暖是否统一并与主色协调？
- [ ] 文字对比度：正文 ≥ 4.5:1，大字 ≥ 3:1？
- [ ] 彩色底白字的徽章/标签是否过深过抢眼，可否改成浅底深字？
- [ ] 状态、涨跌、图表系列是否只靠颜色区分？

## 5. 深度

- [ ] 阴影是否在固定的几级里，并与元素的 Z 轴层级对应（按钮小、下拉中、模态大）？
- [ ] 凸起/凹陷效果是否符合「光从上方来」？高光是否用了半透明白（应手挑颜色）？
- [ ] 拖拽、按下等交互是否有阴影变化反馈？
- [ ] 扁平风格是否可用明暗或实心阴影表达层次？
- [ ] 是否可以用重叠（卡片跨背景交界等）增加层次？重叠图片之间是否有间隙？

## 6. 图片

- [ ] 照片质量是否足够？是否还是占位图？
- [ ] 图片上的文字在亮部和暗部是否都可读（叠加层/降对比/着色/文字光晕）？
- [ ] 图标是否被放大或缩小到绘制尺寸之外？favicon 是否单独绘制？
- [ ] 截图是否被缩到看不清？
- [ ] 用户上传图片是否放在固定比例容器里裁切？是否会与背景融在一起？

## 7. 细节与空状态

- [ ] 边框是否过多？能否改用阴影、背景色差或间距？
- [ ] 空状态是否设计过（插画 + 明确行动按钮 + 隐藏无用的筛选等）？
- [ ] 平淡时，能否用强调边框、背景色/渐变/低对比图案、图标化列表、自定义复选框等提升？
- [ ] 圆角是否全局一致（没有直角圆角混用）？
- [ ] 下拉菜单、表格、单选组是否困在「标准样子」里，而它们本可以更有层次？
- [ ] 字体、颜色、圆角、文案语气是否表达了一致的个性？
