## 1. 从零开始

### 从功能开始，而不是从布局开始
- 「应用」是一组功能的集合。没做出功能之前，你并不知道导航需要承载什么信息。
- 做法：挑一个具体功能，列出它需要的字段和操作，先把这一块做出来。很多时候功能本身就是页面的全部。
- 反例：一上来就纠结顶部导航还是侧边栏、Logo 放哪、内容要不要容器。

### 细节稍后再定
- 早期不要纠结字体、阴影、图标。可以用粗头记号笔在纸上画，物理上就不可能抠细节，适合快速试多种布局。
- 进入高保真后仍先**用灰度**做：被迫只靠间距、对比度、尺寸建立层次，结果更清晰，之后用颜色强化更容易。
- 线框和草图是一次性的：用来探索，决定后就丢掉，尽快去做真实的东西。

### 不要一次设计太多
- 抽象地预想每个边界情况（2000 个联系人怎么显示、错误提示放哪、两个日程重叠怎么办）只会让人卡住。
- 做法：短周期循环——设计下一个功能的简单版本 → 实现 → 在真实界面里解决冒出来的问题 → 回到设计做下一个。
- **做个悲观主义者**：不在设计里暗示还没准备好实现的功能。例：评论系统预留了附件，结果附件很难做，整个评论系统都被搁置；没附件的评论系统也比没有评论系统强。难的部分晚点设计，先上能用的最小版本。

### 选择个性
设计的个性由几个具体因素决定：
- **字体**：衬线 → 优雅、经典；圆润无衬线 → 活泼；中性无衬线 → 朴素，让其他元素承担个性。
- **颜色**：蓝色稳妥、熟悉；金色显得昂贵精致；粉色更轻松不严肃。不必迷信色彩心理学，但可用来解释直觉。
- **圆角**：小圆角中性；大圆角活泼；无圆角严肃正式。**同一界面里不要混用直角和圆角。**
- **文案语气**：非人称、正式的措辞显得专业；友好口语化的措辞显得亲切。文字在 UI 里无处不在，选词和选颜色同样重要。
- 拿不准时，看目标用户常用的其他产品是什么调性；但不要照搬直接竞品，否则像二流仿品。

### 限制你的选择
- 选项无限时，每个小决定都是折磨（12 还是 13px？阴影 10% 还是 15%？）。
- 做法：预先定义一组有限的值，之后只在其中选。前期辛苦一次，换来以后不用反复决策。
- **排除法挑值**：先猜一个，再对比两侧相邻值；通常两个明显不对，剩下的就是答案；若边上的值最好，以它为中心再比一轮。
- 需要系统化的东西：字号、字重、行高、颜色、外边距、内边距、宽度、高度、阴影、圆角、边框宽度、不透明度……凡是你发现自己在反复纠结的低层决定。不必一次定全，但始终用系统化思维，尽量不做第二次同样的小决定。

## 2. 层次决定一切

### 并非所有元素都同等重要
- 视觉层次（元素之间的相对重要程度）是让界面「像设计过」最有效的工具。
- 所有东西都在抢注意力时，界面显得嘈杂，像一面没有重点的内容墙。有意弱化次要和辅助信息、突出最重要的元素，即使配色、字体、布局不变，也会立刻好看很多。

### 字号不是一切
- 只靠字号控制层次，往往导致主要内容过大、次要内容过小。
- 做法：用**字重**和**颜色**分担。主元素用更粗的字重，字号保持合理即可；辅助文字用更柔和的颜色而不是更小的字号——既表明是次要的，又不损害可读性。
- 文字颜色两到三种就够：深色（主要内容，如标题）、灰色（次要，如日期）、浅灰（三级，如页脚版权）。
- 字重两种就够：正文 400 或 500（视字体而定），强调 600 或 700。
- UI 里不要用低于 400 的字重；细字重只适合大标题。想弱化文字时用浅色或小一号，而不是细字重。

### 不要在彩色背景上用灰色文字
- 白底上浅灰之所以有效，是因为它**降低了与背景的对比度**。彩色底上真正有效的是让文字颜色更接近背景色。
- 白色加透明度虽然降低了对比度，但文字会发灰、发脏，压在图片或花纹上时背景还会透出来。
- 做法：取与背景**同色相**的颜色，手动调饱和度和明度直到合适。

### 通过弱化来强调
- 主元素不够突出、又加不了东西时，反过来弱化与它竞争的元素。
- 例：激活的导航项不突出 → 把未激活项改成更柔和的颜色。侧边栏和主内容抢视线 → 去掉侧边栏背景色，让它直接坐在页面背景上。

### 标签是最后手段
- 「标签：值」的展示让每条数据同等重要，无法建立层次。
- **可能根本不需要标签**：格式能说明（邮箱、电话、价格）；上下文能说明（员工卡片里姓名下方的「客户支持」就是部门）。
- **把标签并进值里**：「库存：12」→「剩余 12 件」；「卧室：3」→「3 间卧室」。合成一个单元后更容易给数据加有意义的样式。
- **必须要标签时把它当辅助内容**（如仪表盘上大量同类数据需要扫读）：标签小一号、颜色更浅、字重更轻，或三者结合。
- **例外：用户按标签查找时**（技术规格页，用户找的是「厚度」而不是「7.6mm」），标签可以更深，值稍浅一点；但值依然重要，别过度弱化。

### 视觉层次与文档层次分开
- 语义标签（h1、h2……）按语义选，样式按视觉层次定。不要因为用了 h1 就把它做得很大。
- 很多区块标题其实更像标签，是辅助内容，应该小；重点是区块内容本身。极端情况可以只在标记里保留标题（为可访问性）而视觉上隐藏。

### 平衡重量与对比度
- 粗体显得突出，是因为它覆盖了更多面积。同样的道理适用于其他元素。
- **用对比度抵消重量**：实心图标视觉上很「重」，放在文字旁会抢眼；无法改变图标重量时，降低它的颜色对比度（更柔和的颜色）。
- **用重量补偿对比度**：1px 浅色边框太弱、加深又显得刺眼时，把边框加粗（如 2px）而保持柔和颜色。

### 语义是次要的
- 每页的操作构成一个重要性金字塔：通常一个主操作、几个次操作、少数三级操作。
- 主操作：实心、高对比背景色。次操作：清晰但不抢眼——描边样式或低对比背景。三级操作：可发现但不显眼——做成链接样式。
- **危险操作**不等于必须又大又红。如果它不是页面主操作，用次级或三级样式；在随后的确认步骤里它才是主操作，这时再用醒目的红色实心按钮。

## 3. 布局与间距

### 从过量留白开始
- 习惯做法是「看着挤就加一点 padding」，结果只到「不算太糟」的程度；真正好看通常需要更多留白。
- 做法：先给明显过多的空间，再往回减到满意。单独看时「有点多」的留白，放在整个界面里往往刚好。
- 密集界面有它的位置（如需要同屏展示大量信息的仪表盘），为了信息密度接受更「忙」的观感是合理取舍——但要**有意识地选择**，而不是默认。

### 建立间距与尺寸系统
- 不要在 120 和 125px 之间纠结；在任意值上逐像素试，既慢又不一致。
- 「都用 4 的倍数」这种线性规则帮不了忙。系统必须考虑**相邻值的相对差距**：小端 12→16 是 33% 的差别，大端 500→520 只有 4%。
- 做法：取一个基准值（16px：好整除，也是浏览器默认字号），用它的分数和倍数构成刻度；小端密、越往上间隔越大，**相邻两个值至少相差约 25%**，否则肉眼难以区分、无法帮你做决定。
- 使用：需要更多空间就取下一个刻度值试试。工作流会快很多，设计也会出现以前没有的一致性。

### 不必填满整个屏幕
- 有 1200–1400px 的画布不代表要用满。只需要 600px 就用 600px；把东西摊开或拉宽只会更难理解。
- 界面各部分独立决定宽度：导航全宽不代表内容也要全宽。每个元素给它需要的空间，别为了与别的东西对齐而把它弄差。
- **缩小画布**：在大画布上难以设计小界面时，先在约 400px 宽的画布上做移动端，满意后再放到大屏，调整小屏上不合理的地方——需要改的往往比想象中少。
- **分栏思考**：窄宽度效果最好的内容在宽屏里显得失衡时，拆成多栏而不是拉宽。例：窄表单旁边把说明文字放到单独一栏，表单本身仍保持最佳宽度。
- 也别硬塞：需要大空间就用，不需要就别觉得有义务填满。

### 网格被高估了
- 12 栏网格本质上只是一组受限的百分比宽度。把所有布局决定外包给网格弊大于利。
- **不是所有元素都该流动**：侧边栏按 3/12 宽度，屏幕变宽它跟着变宽（浪费主内容空间），变窄又会缩到不合理宽度。更好：侧边栏固定宽度、按内容优化，主内容区弹性填满剩余空间，内部再用自己的网格。组件内部同理，不是真想让它缩放就别用百分比。
- **需要时才缩小**：登录卡按栏数定宽，会出现中屏比大屏还宽的荒唐情况。知道 500px 最合适，就给 `max-width: 500px`，只在屏幕不够时才被迫缩小。

### 相对尺寸不能等比缩放
- 不要假设「A 在小屏缩 25%，B 也该缩 25%」。例：桌面正文 18px、标题 45px（2.5em）；手机正文降到 14px，标题若仍 2.5em 就是 35px，太大——合适的大约 20–24px，只有正文的 1.5–1.7 倍。
- 规律：大元素在小屏上要比小元素缩得更快；小屏上大小元素之间的差距应该更小。
- 组件内部也一样：按钮 padding 不要用 em 绑定字号。等比缩放出来的大按钮显得松、小按钮显得紧；大按钮应该给更宽松的 padding，小按钮给更紧凑的 padding，让它们看起来是真正「更大/更小的按钮」，而不是被放大缩小。放弃「一切都要成比例」，给自己独立微调的自由。

### 避免含糊的间距
- 没有边框或背景色分隔时，分组全靠间距表达。标签下方和输入框下方间距相同，就看不出哪个标签属于哪个输入框——轻则费解，重则填错字段。
- 做法：**组与组之间的间距必须明显大于组内元素之间的间距**。同样适用于：标题上方空间不足（标题和上一段粘在一起）、列表项间距等于行高、横向排列的组件。

## 4. 文字设计

### 建立字号刻度
- 大多数界面字号太多（10–24px 每个整数都用到）。无系统 → 不一致 + 拖慢工作流。
- 线性刻度不行：小端需要细的跳跃，大端不该在 46 和 48px 之间纠结。
- **模块化比例**（如 4:5、2:3、黄金比例）数学上漂亮，但实际有两个问题：会产生小数像素（各浏览器取整不一致，如要用请自己先取整）；对界面来说跳跃太粗（3:4 只得到 12、16、21、28，实际总想在中间再插值）。
- **手工刻度**更实用：直接挑值，完全掌控有哪些尺寸。默认刻度见 tokens.md。
- **不要用 em 定义字号刻度**：嵌套时 em 相对父级计算，实际字号会落到刻度之外（1.25em 里再套 .875em 得到 17.5px）。用 px 或 rem。

### 使用好字体
- 最稳：中性无衬线（如 Helvetica），或直接用系统字体栈——不出彩，但用户已经习惯。
- 过滤：通常忽略可用样式少的字体。在 Google Fonts 等目录按「样式数」筛选 10+（含斜体），能淘汰绝大多数选项。字重多的字体一般做得更用心。
- 为可读性优化：标题用字体字距更紧、x 高度更小；小字号用字体字距更宽、x 高度更高。主 UI 文本避免用 x 高度小的窄体。
- 相信大众：按流行度排序能有效缩小范围，挑有个性的衬线字体时尤其有用。
- 偷师：看你喜欢的、设计讲究的网站用了什么字体。
- 多看精心设计的排版，直觉自然会养成。

### 控制行长
- 段落不要随布局拉宽。最佳阅读体验是**每行 45–75 个字符**；Web 上最简单的做法是宽度 20–35em。超过 75 有时也行，但是冒险。
- 段落与图片等大组件混排时，即使内容区整体更宽，**仍然单独限制段落宽度**。同一内容区用不同宽度起初反直觉，但结果几乎总是更精致。

### 按基线对齐，而不是居中
- 同一行混用不同字号（卡片左上大标题、右上小号操作链接）时，本能的垂直居中在文字靠得近时会显得别扭。
- 做法：按**基线**对齐（`align-items: baseline`，iOS 用 `.firstTextBaseline`），利用眼睛已经感知到的参考线，更简洁干净。

### 行高要成比例
- 「1.5 行高」只是起点。行间距的作用是换行时帮眼睛找到下一行。
- **与行长成正比**：行越长，眼睛回跳距离越远越易迷失，需要更大的行高——窄内容 1.5 可以，宽内容可能需要到 2。
- **与字号成反比**：小字需要更大行高；大标题眼睛不需要帮助，行高 1 也完全可以。

### 不是每个链接都需要颜色
- 段落里的链接要醒目、像可点击。但在几乎所有东西都是链接的界面里，这种处理会喧宾夺主。
- 做法：大多数链接用更粗的字重或更深的颜色等低调方式强调；真正辅助性的、不在主路径上的链接，可以默认不强调，只在 hover 时加下划线或变色。

### 考虑对齐方式
- 文本对齐方向跟随语言方向；中英文绝大多数文本左对齐。
- **长文本不要居中**：居中适合标题和短的独立文本块；超过两三行几乎总是左对齐更好。若一组居中文本里有一块太长，最简单的办法是改写得更短——也让设计更一致。
- **表格里数字右对齐**：小数点位置一致，便于比较。
- **两端对齐要配合断字**（`hyphens: auto`），否则词间出现难看的空隙。它适合模仿印刷品的场景（在线杂志、报纸），其他场合左对齐同样好，属偏好。

### 有效使用字间距
- 一般信任字体设计者，不动字间距。以下情况例外：
- **收紧标题**：为小字号设计的字体（如 Open Sans）字距较宽，用作标题时可略收紧（约 -0.05em），模仿专用标题字体的紧凑感。反过来不行：标题字体放到小字号，加大字距也很少好看。
- **全大写加宽**：字体字距是为大小写混排优化的；全大写字母等高、缺少辨识特征，加大字距（约 +0.05em）提高可读性。

## 5. 使用颜色

### 用 HSL 代替 Hex
- Hex/RGB 下视觉相近的颜色在代码里毫无相似性。HSL 用人直觉感知的属性描述颜色：
  - **色相**：色环上的位置（0° 红、120° 绿、240° 蓝）。
  - **饱和度**：鲜艳程度，0% 为灰；饱和度 0 时色相无意义。
  - **明度**：离黑白多近，0% 黑、100% 白、50% 为该色相的纯色。
- 别和 HSB 混淆：HSB 的 100% 亮度只有在饱和度 0 时才是白色；设计软件多用 HSB，浏览器认的是 HSL。

### 你需要的颜色比想象的多
- 配色生成器给的「五个完美颜色」做不出真正的产品。完整色板分三类：
  - **灰色**：文字、背景、面板、表单控件……界面大部分是灰色。需要 8–10 级；纯黑显得不自然，从深灰起步到白。
  - **主色**：一到两个，用于主操作、激活态等，决定整体观感。需要 5–10 级深浅：极浅的做提示框背景，深的做文字。
  - **强调色**：吸引注意（如用黄/粉/青绿标新功能）和语义状态（红=危险确认、黄=警告、绿=正向趋势）。用量少，但也要多级深浅。需要区分同类元素（图表线、日历事件、标签）时还要更多强调色。
- 复杂 UI 用到约十种颜色、每种 5–10 级并不罕见。

### 预先定义色阶
- 不要用 `lighten()/darken()` 之类即时生成深浅，否则会出现 35 种看起来一样的蓝。预先定义固定色阶，只从中选。
- 构建步骤：
  1. **选基色**（500）：经验法则是「适合做按钮背景的那个」。没有「从 50% 明度开始」之类的硬规则，靠眼睛。
  2. **定两端**：最深（900，通常用作文字）和最浅（100，用作元素底色）。用提示框组件（浅底+深字）来挑最合适。先取与基色相同色相，再调饱和度和明度。
  3. **填中间**：先定 700 和 300（各自是两侧的完美折中），再填 800、600、400、200。每色至少 5 级，想宽裕就 9–10 级。
  - 灰色同理，基色不重要：最深灰 = 项目里最深的文字色，最浅灰 = 最浅的背景色，然后填中间。
- 这不是科学：系统化方法用来起步，用起来后免不了微调饱和度或明暗，相信眼睛而不是数字。但尽量不随手加新色阶，否则等于没有色彩系统。

### 别让明度杀死饱和度
- HSL 中明度接近 0% 或 100% 时饱和度的效果会减弱。所以色阶越远离 50%，越要**提高饱和度**，否则浅色和深色发灰发脏（色阶的饱和度曲线大致呈 U 形）。
- **利用感知亮度**：不同色相天生亮度不同（黄比蓝亮，即使 HSL 明度相同）。感知亮度在色环上有三个低谷（红、绿、蓝）和三个峰（黄、青、品红）。
- **旋转色相改变亮度**：只调明度会让颜色更接近白/黑而损失强度。要变亮，把色相往最近的亮色相（60°、180°、300°）转；要变暗，往最近的暗色相（0°、120°、240°）转。适合黄色等浅色相：深色阶逐渐偏向橙色，得到温暖饱满的深色而不是暗淡的棕色。可与调明度结合，但旋转不要超过 20–30°，否则就成了另一种颜色。

### 灰色不一定是灰色
- 纯灰饱和度为 0，但很多看起来是灰的颜色其实带饱和度，产生冷暖感（类似暖白/冷白灯泡）。
- 冷灰：加一点蓝；暖灰：加一点黄或橙。
- 和彩色一样，浅灰和深灰要提高饱和度，否则相比 50% 附近的灰会显得褪色。
- 加多少完全看偏好：微微带温度就少加，想明显倾向就多加。

### 无障碍不等于丑
- WCAG：正文（约 18px 以下）对比度至少 4.5:1，大字至少 3:1。浅底深字容易满足，彩色文字就难了。
- **翻转对比度**：彩色底白字要满足 4.5:1，底色往往得很深，会抢走不该是重点的元素的注意力。改为浅色底+深色同色相文字，颜色仍在辅助信息，但不扎眼。
- **旋转色相**：深色面板上的彩色次要文字，只调明度饱和度往往得接近纯白才达标。把色相转向更亮的色相（青、品红、黄），既达标又保持彩色，且与主文字区分开。

### 不要只依赖颜色
- 红绿色盲用户分不清指标是变好还是变坏。加图标（上/下箭头）表达正负。
- 图表多系列时，不要用几种完全不同的色相，改用同色系的**明暗对比**——色盲用户分辨明暗比分辨色相容易得多。
- 颜色用来强化已经表达的信息，而不是唯一的表达手段。

## 6. 营造深度

### 模拟光源
- 规则只有一条：**光从上方来**。凸起的面板上沿受光更亮、下沿背光更暗；凹陷的面板上沿有阴影、下沿受光。
- 先想清楚元素的轮廓（凸起/凹陷），再模拟光照：
  - **凸起元素**（如按钮）：人通常略向下看，所以露出一点上沿、看不到下沿。上沿用更浅的颜色（顶部边框，或 `inset 0 1px 0` 的浅色内阴影）；**手挑浅色而不是叠半透明白**，后者会吸走底色饱和度。下方加一个小的、略向下偏移、模糊很小的暗阴影（凸起物挡住了下方的光），边缘应清晰。
  - **凹陷元素**（「井」、输入框、复选框）：只看得到下唇，下唇朝上受光，用底部浅边框或负偏移的浅色内阴影；顶部加一个小的、略向下偏移的暗色内阴影（上沿挡光）。
- 别沉迷：借用几个真实世界的视觉线索即可，不必追求照片般逼真，否则界面繁杂不清。

### 用阴影表达高度
- 阴影把元素放在虚拟 Z 轴上：模糊小 → 刚离开背景；模糊大 → 更靠近用户。越近越吸引注意。
- 小阴影：按钮等希望被注意但不抢整页的元素。中阴影：下拉菜单等需要浮于界面之上的元素。大阴影：模态对话框，必须抓住注意力。
- **建立高度系统**：通常 5 级就够。先定最小和最大，再线性填中间。
- **阴影与交互结合**：可拖拽排序的列表项被按住时加阴影，表示它浮起、可拖动；按钮按下时阴影变小或消失，表示被按进页面。
- 思路转换：不是想「要什么阴影」，而是想「元素在 Z 轴哪一层」，再分配对应阴影。

### 阴影可以有两层
- 精致阴影常常是两层，各有分工：
  - 第一层：较大、柔和，较大的垂直偏移和模糊——模拟直射光在物体后方投下的影子。
  - 第二层：紧凑、更暗，偏移和模糊都小——模拟物体正下方连环境光都照不到的区域。
- 好处：大阴影保持柔和的同时，让靠近边缘的阴影更清晰。
- 随高度变化：物体离表面越远，第二层的小暗影越淡。高度越高，第二层越弱，最高一级几乎或完全不要第二层。

### 扁平设计也能有深度
- **用颜色表达深度**：同色系里，越浅越近，越深越远。元素比背景浅 → 凸起；比背景深 → 凹陷。非扁平设计同样适用。
- **实心阴影**：短的、只有垂直偏移、**零模糊**的阴影，让卡片或按钮轻微浮起，又不破坏扁平感。

### 重叠元素制造层次
- 让卡片跨在两种背景的交界处，而不是完全包含在某个区域内；或让元素比父容器高、两侧溢出；轮播控件压在内容边缘上。
- 图片重叠容易互相冲突：给图片加一圈与背景同色的「隐形边框」，留出间隙，既有层次又不难看。

## 7. 处理图片

### 使用好照片
- 烂照片能毁掉其他方面都很好的设计。需要非常特定的照片就请专业摄影师（光线、构图、色彩是多年功夫）；需求通用就用高质量图库（包括免费图库）。
- 不要用占位图设计、指望之后用手机拍几张替换——永远行不通。

### 文字需要一致的对比度
- 背景照片明暗变化大：白字在亮区看不清，黑字在暗区看不清。问题在图，不在字——要降低图片的动态范围。
- **叠加层**：半透明黑色压暗（配浅色字），半透明白色提亮（配深色字）。代价是整张图都变暗/变亮。
- **降低图片对比度**：更可控；会改变整体明暗感，记得调亮度补偿。
- **单色着色**：降对比度 → 去饱和 → 用「正片叠底」叠一层纯色。也能让图片贴合品牌色。
- **文字阴影**：想保留更多图片动态时，用大模糊、零偏移的文字阴影做成柔和光晕，只在最需要的地方提高对比；可与降低整体对比度结合，降得少一点。

### 一切都有预定尺寸
- **不要放大图标**：为 16–24px 绘制的图标放大 3–4 倍会显得笨重、缺细节。手里只有小图标时，把它放进一个有背景色的形状里，图标保持接近原尺寸，外形填满大空间。
- **不要缩小截图**：整屏截图缩 70% 后，16px 字变成 4px，没法看。改为：在较小屏幕尺寸（如平板布局）截图，缩放幅度小；只截局部；或重绘一个去掉细节、用线条代替小字的简化 UI 示意。
- **也不要缩小图标**：大图标缩到很小会糊。最典型的是 favicon：别把 128px Logo 缩到 16px，按目标尺寸重绘一个极简版，自己掌控取舍。

### 小心用户上传的内容
- **控制形状和尺寸**：按原始比例展示会打乱布局。放进固定比例容器并裁切（`object-fit: cover` / `background-size: cover`；iOS 用 `scaledToFill` + `clipped`）。
- **防止背景渗色**：图片背景色和界面背景相近时边界会消失。不要用边框（会与图片颜色冲突），用很淡的内阴影或半透明内描边（如 `inset 0 0 0 1px` 10% 黑），多数人察觉不到它的存在。

## 8. 收尾细节

### 增强默认元素
- 不一定要加新元素，可以「升级」已有的：
  - 列表项目符号换成图标（对勾、箭头通用；也可按内容用更具体的，如安全特性用锁）。
  - 推荐语的引号放大、上色，变成视觉元素。
  - 链接做特殊样式：改颜色和字号，或加一条粗的彩色下划线部分压住文字。
  - 表单用自定义复选框和单选按钮，选中态用品牌色代替浏览器默认色，往往就从乏味变精致。

### 用强调边框加点颜色
- 不会画图也能加亮点：在卡片顶部、激活导航项下方、提示框侧边、标题下方（短横线）、甚至整个页面顶部加一条彩色边。加一个彩色矩形不需要任何美术功底，却能明显提升「设计感」。

### 装饰背景
- 层次、间距、排版都对但仍平淡时：
  - **换背景色**：突出单个面板，或区分整页的不同区块。想更有活力可用轻微渐变，两端色相相差**不超过 30°**。
  - **重复图案**：铺满或只沿一条边重复，图案与背景对比度要低，保证可读。
  - **单个图形或插画**：在特定位置放一两个简单几何形状、一小块图案或简化的世界地图，同样保持低对比，不干扰内容。

### 不要忽视空状态
- 精心准备的示例数据很漂亮，用户首次进入时看到的却是空白页。依赖用户内容的功能，**空状态应该是优先事项，而不是事后补丁**。
- 做法：放图片或插画吸引注意，突出引导下一步的行动按钮；内容为空时，筛选、标签等辅助 UI 可以整体隐藏，没内容时它们没有作用。
- 空状态是用户对新产品/功能的第一印象，要做得有吸引力。

### 少用边框
- 边框不是区分元素的唯一手段，用多了界面忙乱。替代方案：
  - **阴影**：勾勒轮廓更含蓄；元素与背景颜色不同时效果最好。
  - **两种背景色**：相邻元素用略有差异的背景色就足以区分；已经有不同背景色又有边框时，试试去掉边框。
  - **加大间距**：拉开距离来区分分组，不引入任何新 UI。

### 跳出框架思考
- 别被组件的「标准样子」束缚：
  - 下拉菜单只是一个浮层，可以分区、多栏、加说明文字和彩色图标。
  - 表格的列不必一列一个数据：不需要单独排序的列可以与相关列合并，形成层次（如姓名下面放邮箱）；单元格里可以有图片、颜色。
  - 重要的单选项可以做成可选卡片，而不是一排小圆圈。
- 约束很有用，但有时一点自由正是让界面更上一层楼的关键。

## 9. 持续提升

- **找出你不会做的决定**：遇到喜欢的设计，问自己「设计师做了什么我想不到的事？」——比如日期选择器里反转背景色、把按钮放进输入框内部、标题用两种文字颜色。这些反直觉的决定是新想法的来源。
- **从零重建你喜欢的界面**：不看开发者工具，自己重做一遍；在找出为什么你的版本和原版不一样的过程中，会自己发现诸如「收紧标题行高」「全大写加字距」「叠加多层阴影」这类技巧。
