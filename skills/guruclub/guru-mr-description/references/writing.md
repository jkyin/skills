# 复杂 MR 写作

仅在问题复杂或模板需要时读取，按实际内容选择章节：

- 背景：具体触发、原行为及影响；是否需要后端协作。
- 根因：bugfix 中被破坏的契约或状态关系，避免把“改了某处”当成根因。
- 关键变化：按功能/模块概括做法和原因，解释理解当前实现必需的取舍。
- 风险与验证：影响面、已执行且有结果的检查、尚待验收的具体场景。
- 已知未处理项：本轮确实存在且未纳入的问题、影响及原因。

例如：播放结束后视频层仍覆盖封面；结束事件只改变播放状态，未恢复封面层级。本次在结束路径统一恢复封面并清理残留画面。验证应分别写明实际通过的场景与尚待设备确认的场景，不照抄此例的结果。

复杂问题也围绕最终实现组织，不保留与评审无关的排查日志或每次方案更替。
