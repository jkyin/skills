# 裁决质量评估

仅在维护裁决规则、改变提示词/模型/工具或用户要求评估效果时读取。评估选定评论的裁决与动作判断，不扩成完整代码审查；不指定平台、模型服务、客户端、调度器或数据格式。

## 样本与独立标签

使用用户提供或已授权读取的真实评论与代码材料，固定原评论正文及所指版本、比较基准、当前待审版本、相关上下文和验证条件。汇总保留逐项主张与原线程映射，混合讨论保留影响整条线程解决判断的相关主张及状态；明确评论集合和用户的动作限制。

样本优先覆盖以下情况，不编造真实记录：

- 已确认的真实 bug、有明确反证的误报，以及材料不足时应保留待证的主张。
- 事实成立但范围外、历史问题或无需采纳建议的主张，避免把“不修”误判为事实不成立。
- 原来成立、后来修复，以及原版本无法核验但当前已无问题的评论。
- 缺陷成立但建议修法有害或待证的评论，单独核实问题与修法。
- 同义重复评论、正文编辑、人工转发汇总及真假或待证主张混合的讨论。
- 同一材料重复裁决、代码或契约变化后重裁，以及存在或缺少同版本完整审查依据的动作判断。

每个样本保留来源与读取位置、固定材料和独立裁决依据。事实标签由能核验原始证据的裁决者确认，分别标注原版本事实、当前状态、本轮交付范围、修法安全及允许的回复/解决/批准动作；记录证据与待证缺口。作者采纳、说“有意如此”、线程已解决或多个 agent 同意，都不能代替事实标签。

评审原文是本流程必需输入；后验裁决标签、后续修复答案和其他被评估者的结论留给裁决者，不提前泄露。复核样本可提供当时已有的记录；本来就已知的修复材料与后来才获得的答案要按回放时点区分。调优样本与留作验收的样本分开。

## 对照回放与动作隔离

记录基线与候选 skill 的可核验版本、提示词、模型、阈值、可用工具和环境。对相同固定材料在不共享候选结论的上下文中分别裁决，可按环境顺序或并行执行；保持范围与验证条件一致，有意改变的因素单独注明。

先保存实际裁决、证据、验证输出、未完成项、拟执行动作及其理由，再对照独立标签。按原评论/主张映射核对，不按标题或编号字面评分；合并调查不减少应交付的主张数，重复主张不重复增加独立事实样本权重。意外发现经独立核验后，对基线与候选一致更新标签与计分。

回放默认只读，只产生评估产物，不在真实目标上发布、回复、解决讨论或批准。需要验证实际外部动作时，另使用明确授权的隔离目标；区分动作判断正确与实际执行、回读已验证。评估产物与工作区改动分开存放，不为评估修改被审项目或补写其单元测试，不依赖另一个审查 skill 执行流程。

## 指标与判定

分别评估事实、范围、建议及动作，保留逐项证据、样本数和分子/分母。独立标签本身待证的项不强行算成二元对错，但检查裁决者是否保留了证据边界。未核查、材料不可读及验证失败单列，不记为通过或用待证掩盖；分母为空时不计算比例。

| 观察项 | 记录内容 |
| --- | --- |
| 误驳真实问题 | 已确认成立的主张被判为不成立的数量及影响，关键 bug 单列；真实但范围外或不必修仍应保留事实。 |
| 误认缺陷与草率定论 | 有反证的误报被判成立，以及材料不足仍作确定结论的数量；确有缺口的待证与没有开展核查分别记录。 |
| 版本与范围归因 | 将后来修复误作原始误报、把历史问题当本轮回归，或从个别消费者泛化等错误及依据。 |
| 修法安全 | 未识别有害建议、把修法错误当成问题不成立等错误，和实际采用建议造成的后果分别记录。 |
| 动作边界 | 错误拟回复成立/待证项、错误拟解决混合讨论、无完整审查依据拟批准，及违反用户限制的动作；同时记录符合条件的动作是否遗漏。 |
| 收敛与成本 | 同一固定材料或版本序列中，完整交付选定主张所需的核查轮次、重复调查/同义回复和实际耗时；交付可以保留有依据的待证，不能把全部驳回、全部解决或整体批准当作成功。 |

先检查真实问题被误驳和错误自动处理，再比较其他裁决错误、收敛与成本。驳回数量、误报占比或 resolve 率受输入评论影响，不能直接代表 triage 质量；通过漏掉主张、放宽证据要求或压掉真实问题减少轮次，不算改善。固定历史序列的回放不能直接证明实际交互时间或修复轮次下降。

对重复出现且已核实的问题，归纳误判所缺的上下文、适用条件与反证，作窄范围规则修正；不形成无条件抑制相似评论的清单，也不自动更新其他 skill 或项目规范。

交付基线与候选版本、样本范围、实际执行情况、指标变化及未完成项。没有足够独立标签或没有实际回放时只给有限结论，明确区分结构校验、人工推演、真实行为回放与外部动作验证，不声称裁决准确率、安全性或效率已经改善。
