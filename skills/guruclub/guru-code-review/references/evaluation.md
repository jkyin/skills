# 评审效果评估

仅在维护评审规则、改变提示词/模型/工具或用户要求评估效果时读取。定义可复核的评估方法，不指定平台、模型服务、执行客户端、调度器或数据格式；日常审查不自动启动评估任务。

## 样本与事实依据

使用用户提供或已授权读取的真实变更，保留材料来源与固定版本。优先覆盖以下情况，不为凑数编造事故、误报或干净样本：

- 已确认漏检：事故、回退或后续修复所对应的真实缺陷，已核实根因、触发路径与影响，且属于当时应审查的变更范围。
- 已确认误报：有反证的既有评论，例如把有效契约误判为缺陷或把历史问题误归因于本轮。
- 已确认有害建议：采纳后会破坏明确契约或正确行为的建议；对应的缺陷主张仍单独核实，真实缺陷也可能附带错误修复建议。
- 经核实的干净改动：在指定范围和契约下没有应报告问题，用于观察评审器是否凭模式猜测或诱导无必要的修改。

回退、评论被采纳、作者说“有意如此”或决定“不重要”，都不能单独充当事实标签。事实成立、是否属于本轮、是否阻塞与建议是否有害分别核实；信息不足的项保留待证，不混入已确认对错。独立裁决者可以是熟悉代码的人或能核验原始证据的独立检查者，不能只靠多个 agent 投票生成事实标签。

每个样本保留以下必要信息，形式可按环境选择：

- 样本标识、材料来源及可读取位置、比较基准与待审版本；连续复审另保留各轮版本和前轮可获得的审查记录。
- 当时可获得的需求、适用指令、完整变更范围、相关上下文，以及影响判断的依赖/工具链条件与允许的验证方式。
- 留给裁决者的事实依据：已确认缺陷或干净范围、触发条件、影响、根因及修复/反证材料；区分确定标签和待证项。

评审输入与裁决依据分开。回放只提供审查当时可获得的材料；后来的修复、回退原因、预期发现和其他评审器结论不提前泄露给被评估者。复审样本可以提供前轮记录，但不能夹带后续答案。调优样本与留作验收的样本分开，避免只适配已看过的答案。

## 对照回放

记录基线与候选 skill 的可核验版本、模型、提示词、阈值、可用工具及相关环境。对相同固定样本使用一致的范围和验证条件；有意改变的因素单独注明，不能将其他条件的差异算成规则收益。

在不共享候选结论的上下文中分别运行基线与候选，可按环境顺序或并行执行。先保存实际报告、验证输出、未完成项和资源开销，再对照裁决依据；人工推演、结构检查与真实行为回放分别记录。样本不可读取或验证不能执行时报告缺口，不能记为通过。

回放默认只读，只产生评估产物，不在真实目标上发布、回复、解决讨论或批准。需要评估外部动作时另使用明确授权的隔离目标；普通远程审查的自动处理规则不作为回放写入依据。评估产物与工作区改动分开存放，不为评估修改被审项目或补写其单元测试。

按根因、触发条件和后果匹配发现，不要求标题或行号字面一致；同一缺陷报告多次只计一次命中，重复另计。将事实判断、范围归因、阻塞判断及建议质量分别裁决；新增的意外发现经独立核验后补入标签，并对基线与候选一致重算，不能直接算误报或只给一方加分。

## 指标与判断

保留样本数、分子、分母及逐项依据；分母为空时不计算比例。待证和未完成项单列，不能通过排除难例宣称整体改善。

| 观察项 | 记录内容 |
| --- | --- |
| 漏检 | 已确认且范围内的真实缺陷数、有效命中数与漏检数；关键缺陷单列，不被总体平均值掩盖。 |
| 误报 | 已确认事实不成立或范围归因错误的缺陷主张数，以及可裁决的缺陷主张总数；真实但非阻塞的问题不因“不需要改”被算成误报。 |
| 有害建议 | 采纳会破坏明确契约或正确行为的建议数量及证据，区分实际造成损害与已证明的潜在后果。 |
| 收敛 | 同一固定版本序列中达到完整 APPROVE 条件的轮次，重复发现数及未收敛样本；预算结束、漏掉问题或提前批准都不算收敛成功。既有版本序列的回放结果不能直接证明真实交互中的修复轮次下降。 |
| 成本与人工负担 | 实际耗时、验证开销及需要人工裁决的事项；没有测量则不推算节省。 |

先核对关键漏检与有害建议，再比较误报、收敛和成本。放宽通过条件、减少覆盖或压掉真实问题换来的少轮次，不能记为改进。出现退化时定位相关规则与样本，作有证据的窄修正；重复出现的问题只有在适用范围明确后才沉淀为规则或项目审查规范。

交付时说明基线与候选版本、样本范围、实际执行情况、指标变化和未完成项。样本不足或缺少独立事实标签时只给有限结论；只有规则文档、结构校验或人工推演时，明确尚未完成行为回放，不宣称漏检率、误报率或效率已经改善。
