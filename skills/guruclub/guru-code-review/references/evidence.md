# 审查证据

仅在确定比较快照、读取远程审查材料或复审时读取。具体工具、认证和平台操作由当前环境的能力与适用指令决定，本 skill 不指定客户端或接口。

## 固定审查快照

确认目标项目、审查请求、比较基准和待审版本，记录可核验的版本标识（例如提交 SHA）。远程请求已声明比较范围时采用其实际快照，不用本地分支猜测替代。

核验变更材料完整性，注意分页、截断、折叠或未展示文件；部分结果不能称为完整变更。源码、删除内容和重命名前后路径须与比较快照对应。本地版本不同或工作区有其他改动时，读取对应版本的材料，不覆盖现有工作。

检查相关讨论、已有审查意见、当前版本的验证状态及必要日志。旧版本成功不能代表当前通过；按风险核对消费者、依赖解析结果和相关历史。

## 范围覆盖记录

从已确认的完整变更范围建立文件清单，保留路径与变更状态，区分删除、重命名或同一路径的不同变更。每项记录为“已审查”或“未审查＋具体原因”；只读取文件不等于完成审查。明确排除的项另记范围依据，不能把检查失败改称范围排除，也不默认忽略锁文件、配置或二进制的契约影响。

按关联风险组织检查，例如将实现、配置、资源和消费者一起核对；语言或职责规则按需加载。分批或复用已有检查不应遗漏清单项，不因已发现一个严重问题提前宣称审查完成。

交付前汇总范围内文件数、已审查数与未审查数，并列出未审查项的原因及其对结论的影响；详细清单可留本轮产物。全部文件已审查仅说明范围覆盖，不保证不存在漏检，也不代表完成运行验收。

## 复用与刷新

已核实的固定快照材料可复用。比较基准、待审版本、相关依赖解析结果或工具链变化时刷新受影响证据；即使版本相同，新讨论、CI 或用户补充仍可能改变结论。

取证结束时核对比较快照是否变化，不能混用版本。持续变化或访问缺口时报告已覆盖部分与未完成项，不以本地辅助分析替代完整远程审查。外部写入前另按 [评论发布规则](comments.md) 核对当前目标与快照。

## 复审收敛

首轮按已确认的完整范围审查。连续复审记录前后比较基准、上次已审版本和本次待审版本；区分“当前比较基准到本次版本”的当前完整范围与“上次已审版本到本次版本”的复审增量，基准变化时说明范围差异。用户明确只查增量时遵从该范围，但增量结论不代表完整审查或满足平台批准条件。

前轮有可核验的覆盖记录与证据，且相关契约仍适用时，可复用未受影响部分，集中检查增量、受影响的调用链与消费者，以及前轮未完成项。更新当前完整范围的文件清单，注明复用证据的来源版本与适用依据；缺少前轮记录时补审，不能默认未改文件已经审过。基准、依赖、工具链或历史变化时重判受影响证据；无法可靠界定影响时扩大至完整审查，不强行沿用增量模式。

沿用稳定发现 ID，区分本轮新增、仍成立、已修复、已证伪与待证，关联相应版本和证据；同一问题有新证据时更新原记录或原线程，不重复发布。已解决的问题因本轮修改重新出现时，记录再次出现的版本及原因。对修复检查相关触发路径和必要验证，不能只凭改了某行或线程已关闭判定修复完成。

按根因关联同类实例，在相关影响范围内一次检查已知入口并说明覆盖，避免逐轮只报告一个实例；不据此扩成无边界的全仓排查。后续发现原始审查范围内、前轮已存在但遗漏的真实缺陷，仍按证据报告，并注明属于前轮漏检；不能为收敛而压掉缺陷，也不能将其归因为修复提交新引入。原始范围之外的历史问题仍按范围边界处理。

不预设必须重复审查的轮数。没有新版本、新证据或未完成的风险检查时，不为等待通过而原样重跑。多轮仍围绕相同根因或契约分歧、缺少实质进展时，交付已确定发现、剩余范围、分歧与所需修改或证据，停止无收益的循环；已有明确任务轮次预算时同时报告预算结束状态。按 [报告裁决](report.md) 保留 REQUEST_CHANGES 或 INCONCLUSIVE 的适用条件，不能因轮次耗尽、暂未新增发现或需要收尾而自动 APPROVE。
