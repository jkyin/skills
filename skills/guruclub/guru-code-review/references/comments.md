# 评论与自动处理

仅在评论内容、目标与写入范围明确后读取。具体发布方式由当前环境支持的能力决定，本 skill 不规定平台接口或载荷格式。

## 授权与形式

远程审查默认执行已明确目标内的报告发布、确定发现评论、相关线程回复与解决，以及符合条件的平台批准；同一目标内的这些动作不再逐项请求确认。用户的只读、草稿、先展示或禁用某动作要求优先，本地范围不触发远程写入。自动处理不包含改代码、提交、推送或合入。

| 动作 | 自动执行条件 |
| --- | --- |
| 发布报告 | 目标与比较快照明确；如实发布结论、范围和验证边界，待证内容不伪装成缺陷。 |
| 发布发现 | 事实达到阈值，触发条件、因果与影响已核验；先检查相同发现是否已有评论。 |
| 回复线程 | 与本轮审查直接相关，有确定的新证据、修复状态或不成立理由；回复原线程，不重复已有同义回复。 |
| 解决线程 | 原问题已修复且必要验证完成，或已明确证伪、重复且已有对应处理；没有关键待证或尚需落实的工作。不同意观点、位置过期、机器人状态变化不构成解决依据。 |
| 平台批准 | 当前完整审查为 APPROVE，必要检查与相关讨论状态满足要求，无关键待证或阻塞事项；写前再核对已审版本与平台限制。本账号已经批准相同版本时不重复执行。 |

报告标签不是平台批准凭证，批准成功也不表示合入。无法满足某动作条件时记录原因，继续其他已确定动作，不为得到完整操作状态而猜测或绕过平台门禁。

发现默认逐条使用平台支持的可解决差异线程。公开报告简述结论、范围、验证边界并链接发现线程，不复制全部发现正文；优先更新本轮自己已有的报告，避免反复新增。用户指定汇总、草稿或原线程回复时遵从指定，不额外复制报告与全部内联正文。

## 发现评论模板

沿用 [审查报告](report.md) 中的发现 ID，不因只发布部分发现而重新编号。发现 ID 与平台生成的评论或线程标识不同；后者用于结果确认，不能替代发现 ID。

```markdown
**[I1] 〈问题标题〉**

在〈可达触发条件〉下，〈变更或实现〉会导致〈具体后果〉。
依据：〈相关代码、调用链或明确契约〉。
影响范围：〈受影响对象及必要边界〉。
建议：〈修复方向〉。
```

简单问题允许压缩成一段，保留发现 ID、触发条件、后果、依据与建议；信息可以合并表达，不强制独立字段：

```markdown
**[I1] 〈问题标题〉**：在〈触发条件〉下，〈代码或契约依据〉会导致〈后果及影响对象〉；建议〈修复方向〉。
```

定位已由差异线程准确提供时，不重复堆叠路径和行号；普通评论补充实际路径与审查版本。因果容易误判时补充基准与待审版本差异，验证缺口影响结论时写明边界，不固定附加免责声明。严重度、置信度等可在影响判断需要时补充，不要求复制整份报告或内部评分过程。

## 汇总评论模板

用户要求汇总时可使用以下模板，沿用选定发现的原 ID；默认自动报告以线程链接代替逐条复述：

```markdown
审查版本：〈基准版本〉 → 〈待审版本〉
审查结论：〈报告中的结论标签〉

- **[I1] 〈标题〉**：〈触发条件、后果与修复方向〉
- **[I3] 〈标题〉**：〈触发条件、后果与修复方向〉

验证与边界：〈相关已验证范围及影响判断的缺口〉。
```

选定发现的汇总不冒充完整报告；完整依据可链接已有报告或评论。无发现时仍可自动发布报告，保留版本、结论和验证边界，省略发现列表；不能因此跳过批准条件。

## 定位与快照

写前核对目标状态与比较快照。快照变化时刷新相关证据、复核发现并重新定位；已修复或失效的发现不继续发布。结论或影响改变时重新核实证据，再按当前目标与用户限制更新结果；同一审查范围内不要求重新确认，涉及新目标或扩面时先澄清。

文本评论定位到当前变更中有效且相关的行，区分新增、删除及上下文两侧。二进制或文件整体问题在平台支持时采用文件级位置；文件不在变更范围、重命名路径无法核实或无法准确定位时，使用普通评论，写清实际路径与审查版本，不挂到无关的最近一行。

核实平台是否支持所需定位与线程能力；不以真实目标的测试写入探测能力。不支持时采用符合既有授权的普通评论或报告具体限制，不承诺普通评论可解决。

## 发布前复核

对每条选定发现分别复核事实与位置，可复用仍有效的证据，不要求重新展开整轮调查：

- 事实：触发路径可达、后果和契约有依据，基准与待审版本的因果关系明确；排除已处理路径、历史问题误归因和重复发现。置信度与阻塞判断分别成立，正文没有超出证据的影响范围。
- 位置：路径、变更侧及行或文件位置属于当前比较快照，能对应正文描述的问题。事实成立不能代替定位校验；无法准确定位时采用上述普通评论退路。

保留报告中的发现 ID，使报告、评论与后续复审可以对应。若复核后发现失效则不再发布，并更新本轮已有结果；结论或影响变化时按当前证据处理，保留修订说明，不重复请求同一范围内的授权。

## 结果确认与恢复

记录每条发现对应的评论或线程标识、目标和审查快照。写入后重新读取实际结果，确认正文、目标、草稿或公开状态；有定位时另确认路径、行或文件位置、关联版本与可解决状态。普通评论没有差异位置，不要求其返回定位版本，在本轮记录中关联审查版本。

重新核对当前比较快照；写入期间发生变化时保留已写标识，刷新受影响证据并说明评论覆盖的版本，不重复创建或声称已覆盖新版本。

请求结果不明时先查询是否已写入，不能盲目重发；无法判定则记录状态未明并停止该项重试。部分成功时分别记录已完成、失败和状态未明项，只重试已确认未完成且仍获授权的项，重试前再次核对目标状态。

发布草稿只处理获授权的指定项，不能连带发布其他草稿。缺少单项发布能力时报告限制；草稿消失本身不证明已公开，须找到对应公开结果，不能假设草稿与公开评论使用相同标识。

平台批准后回读当前版本对应的批准状态；返回成功不足以证明批准仍适用于新版本。版本变化则重新审查受影响证据并重判，不声称旧批准覆盖新版本。

完成后分别报告发布、回复、解决和平台批准的实际结果、可用链接与未完成项，不把草稿、报告标签或未核实写入宣称为已公开发布或已批准。
