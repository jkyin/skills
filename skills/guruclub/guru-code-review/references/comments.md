# 评论发布规则

仅在评论内容、目标与写入范围明确后读取。具体发布方式由当前环境支持的能力决定，本 skill 不规定平台接口或载荷格式。

## 授权与形式

只审查默认交付报告。创建草稿也需要写入授权；公开发布、解决线程、平台批准和合入分别处理。用户已明确授权发布本轮展示的发现及目标时，不重复询问同一内容。

遵从用户指定的草稿、公开、汇总或既有线程回复形式。公开发现默认逐条使用平台支持的可解决差异线程；不额外复制一份汇总。已有汇总而要求补内联时保留汇总，可链接原评论减少正文重复。

## 发现评论模板

沿用 [审查报告](report.md) 中的发现 ID，不因只发布部分发现而重新编号。发现 ID 与平台生成的评论或线程标识不同；后者用于结果确认，不能替代发现 ID。

```markdown
**[I1] 〈问题标题〉**

在〈可达触发条件〉下，〈变更或实现〉会导致〈具体后果〉。
依据：〈相关代码、调用链或明确契约〉。
影响范围：〈受影响对象及必要边界〉。
建议：〈修复方向〉。
```

简单问题允许压缩成一段，保留发现 ID、触发条件、后果、依据与建议；信息可以合并表达，不强制独立字段：

```markdown
**[I1] 〈问题标题〉**：在〈触发条件〉下，〈代码或契约依据〉会导致〈后果及影响对象〉；建议〈修复方向〉。
```

定位已由差异线程准确提供时，不重复堆叠路径和行号；普通评论补充实际路径与审查版本。因果容易误判时补充基准与待审版本差异，验证缺口影响结论时写明边界，不固定附加免责声明。严重度、置信度等可在影响判断需要时补充，不要求复制整份报告或内部评分过程。

## 汇总评论模板

仅在用户明确要求汇总时使用，沿用选定发现的原 ID：

```markdown
审查版本：〈基准版本〉 → 〈待审版本〉
审查结论：〈报告中的结论标签〉

- **[I1] 〈标题〉**：〈触发条件、后果与修复方向〉
- **[I3] 〈标题〉**：〈触发条件、后果与修复方向〉

验证与边界：〈相关已验证范围及影响判断的缺口〉。
```

选定发现的汇总不冒充完整报告；完整依据可链接已有报告或评论。无发现且用户明确要求发布结论时，保留版本、结论和验证边界，省略发现列表。

## 定位与快照

写前核对目标状态与比较快照。快照变化时刷新相关证据、复核发现并重新定位；已修复或失效的发现不继续发布。正文或影响实质改变时先展示修订内容，不能用旧授权发布不同结论。

文本评论定位到当前变更中有效且相关的行，区分新增、删除及上下文两侧。二进制或文件整体问题在平台支持时采用文件级位置；文件不在变更范围、重命名路径无法核实或无法准确定位时，使用普通评论，写清实际路径与审查版本，不挂到无关的最近一行。

核实平台是否支持所需定位与线程能力；不以真实目标的测试写入探测能力。不支持时采用符合既有授权的普通评论或报告具体限制，不承诺普通评论可解决。

## 发布前复核

对每条选定发现分别复核事实与位置，可复用仍有效的证据，不要求重新展开整轮调查：

- 事实：触发路径可达、后果和契约有依据，基准与待审版本的因果关系明确；排除已处理路径、历史问题误归因和重复发现。置信度与阻塞判断分别成立，正文没有超出证据的影响范围。
- 位置：路径、变更侧及行或文件位置属于当前比较快照，能对应正文描述的问题。事实成立不能代替定位校验；无法准确定位时采用上述普通评论退路。

保留报告中的发现 ID，使报告、评论与后续复审可以对应。若复核后发现失效则不发布并说明原因；若结论或影响实质改变，先展示修订内容。仅调整准确位置或表述而未改变已授权发现，不重复询问同一发布授权。

## 结果确认与恢复

记录每条发现对应的评论或线程标识、目标和审查快照。写入后重新读取实际结果，确认正文、目标、草稿或公开状态；有定位时另确认路径、行或文件位置、关联版本与可解决状态。普通评论没有差异位置，不要求其返回定位版本，在本轮记录中关联审查版本。

重新核对当前比较快照；写入期间发生变化时保留已写标识，刷新受影响证据并说明评论覆盖的版本，不重复创建或声称已覆盖新版本。

请求结果不明时先查询是否已写入，不能盲目重发；无法判定则记录状态未明并停止该项重试。部分成功时分别记录已完成、失败和状态未明项，只重试已确认未完成且仍获授权的项，重试前再次核对目标状态。

发布草稿只处理获授权的指定项，不能连带发布其他草稿。缺少单项发布能力时报告限制；草稿消失本身不证明已公开，须找到对应公开结果，不能假设草稿与公开评论使用相同标识。

完成后报告实际结果、可用链接与未完成项，不把草稿或未核实写入宣称为已公开发布。
