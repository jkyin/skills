# GuruClub 本地 Pod 引用

仅在实际 GuruClub 主项目检查 `Podfile.rb`；独立 Pod 模块不套用此流程。

用 `rg -n 'local_pod|path:.*\.\./' Podfile.rb` 定位，再阅读相关声明，区分注释和实际引用。报告本轮待提交内容是否仍依赖本机路径。

发现引用后，只读检查声明指向的实际模块路径、未提交内容、当前分支、远端及对应已发布版本/远端分支。不要假定相邻目录、同名 origin 分支或 upstream 一定存在。无法确认远端是否含所需提交时，保留缺口。

- 已有正式版本完整包含本次所需代码：可准备与项目约定一致的 `pod 'Name'` 及版本配置。
- 依赖尚未发正式版但远端分支已含所需代码：可准备 `remote_pod 'Name', branch: '已核实分支'`。
- 所需代码仍未提交或未推送：不能通过改成远端引用让检查表面通过。展示模块差异、所需提交/推送与主项目依赖 diff，取得跨仓库操作授权后再继续。

提交主项目不授权修改、提交或推送依赖仓库。已获明确跨仓库范围授权时继续执行，不按每一步重复确认。

依赖引用修改获授权后，根据项目要求运行必要的 `bundle exec pod install`，检查 Podfile.lock 差异与依赖来源；不为消除无关本地状态而全量更新依赖。最终确认本轮交付不依赖不可取得的本机代码，剩余缺口如实说明。
