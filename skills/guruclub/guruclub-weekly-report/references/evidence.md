# 周报证据与归属

确认范围后再读。


只访问本次确认的来源。项目会话用当前可用的任务列表/读取工具检索，长历史按时间与具体项目缩小范围；文档和手工材料按用户提供范围处理。不要为了补足表格擅自扩展到其他项目。

确认来源包含 GitLab 时：

- 使用 `glab` CLI/API；GuruClub 默认 MR 入口是 `https://git.gelonghui.com/ios/guruclub/-/merge_requests`。认证或网络不可用时报告具体缺口，不改用 GitLab 浏览器自动化，不编造状态。
- 同时检查本周相关的已合并工作和仍在处理的工作；分页读取，结合会话、提交或实际交付信息核对用户归属、时间和实质进展。
- `updated_at` 或评论活动只能用来发现候选项，不能证明本周做了开发。只 review、解决讨论、同步分支、跑 CI 等过程不单独算业务成果。
- 上周完成、本周仅完成集成交付的内容，只表达本周推进，不重复说成本周新开发；本周没有实质进展的旧任务不机械照搬。
- 同一成果在多个 MR、分支或项目集成中出现时去重，避免把代码搬运再次算成功能；确有新的组合兼容问题修复可单列。

对每项内部保留“具体产出、用户归属、本周发生的工作、当前阶段、可验证依据、真实阻塞”。证据仅用于核验，不把工程活动清单塞入周报。缺证据的完成、上线、验收结论不得补写；必要时单独告诉用户待核实点。
