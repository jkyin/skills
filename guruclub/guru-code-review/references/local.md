# 本地范围与比较基准

仅在本地审查时读取。远程审查请求的比较快照由 [审查证据](evidence.md) 处理。

## 范围优先

先采用用户指定的对象，区分未暂存、已暂存、全部未提交改动、单个提交、两个快照或分支相对目标的变更。全部未提交改动还应按范围识别未跟踪文件；审查合并提交时确认要比较的父版本。

用户只说“我的改动”且存在多个合理范围时，先列出紧凑清单再确认。明确范围时不反复询问，也不混入其他范围。

## 比较基准

采用用户指定且可核验的基准。未指定时结合已知合并目标、有效项目约定与仓库实际默认分支判断，并说明依据；默认分支只是候选，不必然是当前工作的目标。

跟踪分支若只是当前开发分支的远端副本，不能用它替代合并目标，否则可能漏掉已推送的改动。分支名和共同祖先距离只能辅助比较，不能证明创建来源。候选冲突、共同祖先不唯一或依据不足时，展示候选并询问必要信息，不按常见分支名称猜测。

明确是在比较两个版本的端点差异，还是比较共同祖先到待审版本的分支变更；二者可能覆盖不同范围。已确定唯一共同祖先时，从该祖先到待审版本的端点比较就是相应的分支变更范围。

记录实际基准与待审版本标识，用一句话说明依据和覆盖范围。历史材料只在解释变更必要时读取。本地报告不执行远程写入，也不因缺少特定平台工具而中止明确的本地审查。
